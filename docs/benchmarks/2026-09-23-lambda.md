# AL2023 memory comparison, 23 September 2026

Decision: use `provided.al2023`, ARM64, **512 MB**, retaining the 3-second
function timeout and 2-second upstream HTTP timeout. This substantially reduces
first-use arrival latency and icon-generation time for a small absolute compute
cost increase. It is the best latency choice among the three tested settings,
not a claim of a globally optimal configuration.

## Method

Built commit `e7d9475` with `CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build`,
using the same binary at 128, 256, and 512 MB. Three temporary functions in
`ap-southeast-1` used the production execution role and API configuration,
AL2023, no provisioned concurrency, and no public triggers. Production was
unchanged during the comparison. All temporary functions and their log groups
were deleted afterward.

The UK host invoked the functions synchronously with HTTP API v2 events for
`/?id=25269` (real Datamall), `/?id=99999` (synthetic), and `/icon?stop=25269`.
Durations come from AWS's invocation REPORT, not UK round-trip measurements.
The synthetic input does not call Datamall. Each real request was checked for
HTTP 200, but the benchmark does not validate arrival prediction accuracy.

Twelve batches reset each function's environment configuration, then invoked
one rotating route first, followed by five requests per route per memory
setting. Memory settings and route order were interleaved. Each configuration
therefore has 12 confirmed cold starts and 180 subsequent invocations, for
**576 successful invocations** total. No function or HTTP errors occurred.
Raw observations are in [the CSV](2026-09-23-lambda.csv).

`Init Duration` identifies Lambda cold initialization. First use of a particular
route can still be slow *after* Lambda initialization: the first real Datamall
request in each environment was consistently much slower than later requests.
The exact cause was not profiled; do not label this entirely as Lambda startup
or upstream service latency. More CPU reduced the observed first-use time.

## Results

All durations are milliseconds. First-use real requests have 12 observations
per configuration; subsequent real requests have 52. Warm icon rows have 60
observations per configuration, excluding invocations with Init Duration.
P95 uses nearest rank; the small samples do not establish production p99.

| Measurement | 128 MB | 256 MB | 512 MB |
|---|---:|---:|---:|
| First real request: median | 1,302.6 | 570.6 | 284.8 |
| First real request: maximum | 1,424.3 | 651.9 | 313.0 |
| Subsequent real request: median | 23.7 | 23.7 | 25.3 |
| Subsequent real request: p95 | 39.6 | 41.4 | 46.8 |
| Warm icon generation: median | 60.5 | 19.8 | 5.7 |
| Warm icon generation: p95 | 104.0 | 40.2 | 19.1 |
| Lambda initialization: median | 102.4 | 103.1 | 103.0 |

Handler duration excludes initialization. For cold invocations, initialization
adds roughly 100 ms in this experiment. All tested settings are adequate for
steady arrival traffic; 512 MB was selected to improve fresh-environment
requests and icons. Memory capacity itself was not the constraint.

## Cost and traffic context

AWS Pricing API's Singapore ARM tier-one duration rate on the test date was
$0.0000133334 per GB-second. These estimates use mean **billed** duration for
subsequent route requests (52 samples each), excluding initialization and first
use. They are not a monthly bill forecast and exclude request fees, API Gateway,
logs, data transfer, taxes, discounts, and free-tier allowances.

| Compute cost per million subsequent requests | 128 MB | 256 MB | 512 MB |
|---|---:|---:|---:|
| Real arrivals | $0.046 | $0.092 | $0.211 |
| Synthetic page | $0.004 | $0.007 | $0.014 |
| Icon | $0.108 | $0.070 | $0.059 |

The preceding seven-day production route query counted 149,578 page/other
requests, 72,912 icons, 68,088 static requests, and 4,787 closest-stop requests.
Icons are about one quarter of traffic. This benchmark deliberately resets
environments frequently, so averaging all benchmark requests would overstate
production's cold/first-use frequency. Earlier production logs showed roughly
0.26% cold starts across all invocations.

This does not measure Singapore mobile page-load time or API Gateway overhead.
The experiment used one real stop during a short time window and did not load
test Datamall, static files, or closest-stop lookup. Recheck production errors,
latency, and billed duration after a representative period on AL2023/512 MB.
